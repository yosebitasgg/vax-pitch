"Cotizar rápido. Cotizar bien. Cotizar primero."

04Plan de demos

Demo 1 · Frontend

  1. Abrir dashboard y sidebar del copiloto.
  2. Crear o usar hilo existente.
  3. Pedir una cotización FTL con ruta y equipo.
  4. Mostrar streaming y respuesta final.
  5. Señalar badges de cotizar_carga_dual, fuentes RAG y confianza.

Demo 2 · RAG

  1. Buscar criterio de margen bajo o ruta transfronteriza.
  2. Mostrar chunks recuperados y fuente.
  3. Remarcar que histórico significa señal, no tarifa vigente.

Demo 3 · MCP/skill

  1. Mostrar inventario de tools MCP.
  2. Ejecutar o explicar cotizar_carga_dual.
  3. Mostrar que la skill pide mínimos y sabe usar MCP o CLI.

Demo 4 · CLI/agente

  1. vax doctor si quieren enseñar salud.
  2. vax quote --dual para cotización.
  3. vax knowledge search "..." para RAG.
  4. Agente: pedir escenarios de margen o recomendación para cliente.

No intenten explicar cada comando. La demo debe probar existencia y valor, no enseñar documentación.

06Defensas rápidas Q&A

¿Por qué RAG si ya hay modelo?

Porque el modelo predice números. La RAG aporta criterio operativo: políticas, checklist, histórico y límites de interpretación.

¿El copiloto puede inventar precios?

Está instruido para no inventar tarifas, márgenes ni disponibilidad. Para números debe usar tools; para criterio debe consultar RAG o marcar pendiente.

¿Por qué MCP?

Porque permite que agentes externos consuman VAX con contratos de tools, auth y resultados estructurados, sin depender de la UI web.

¿Qué pasa con baja confianza?

La respuesta debe marcar revisión humana. Comercial puede usar la precotización como guía, no como cotización final automática.

¿Qué queda pendiente?

Monitoreo de drift, feedback real en operación, retraining mensual y ampliar scope a LTL cuando haya peso/volumen confiable.

07Checklist antes de presentar
  • Abrir el deck final en pantalla completa: pitch/final/index.html.
  • Tener preparado el frontend y una sesión válida.
  • Tener listo un prompt corto para cotización y uno para RAG.
  • Probar comandos de CLI antes de iniciar.
  • No prometer disponibilidad de carriers ni tarifa vigente desde histórico.
  • Si falla Claude por billing o API, decir: "El flujo preserva conversación y muestra error; el fallback local mantiene pruebas de desarrollo".
  • Cerrar siempre con el valor comercial, no con la arquitectura.
