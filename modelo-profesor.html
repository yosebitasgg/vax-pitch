Capitulo III · Por que LightGBM

El precio no se comporta como linea recta.

Las relaciones relevantes son interacciones: origen, destino, equipo, direccion, accesoriales y recencia cambian juntos.

Modelos lineales. Fueron utiles para auditar variables, pero castigaban rutas raras y no capturaban saltos por equipo o frontera.

Arboles boosting. Permitieron capturar cortes no lineales sin exigir que nosotros fijaramos todas las interacciones manualmente.

Validacion temporal. Evaluamos en datos posteriores, porque el objetivo real es cotizar embarques futuros, no memorizar el historico.

La metrica tenia que castigar el error comercial, no premiar explicacion aparente. por eso R2 queda secundario

Capitulo VI · Que significa cada metrica

R2 no fue la metrica principal.

El profesor tiene razon: R2 puede inflarse al agregar variables. Por eso usamos metricas de error y tolerancia.

MAE / RMSE

Error en pesos

MAE dice cuanto nos equivocamos en promedio. RMSE castiga mas los errores grandes.

MAPE / WAPE

Error relativo

MAPE promedia porcentajes por embarque. WAPE pondera por monto y es mas estable con tickets grandes.

Within ±15%

Utilidad comercial

Pregunta practica: en cuantos embarques la prediccion cae dentro de una tolerancia negociable.

p10/p90

Incertidumbre

No es exactitud puntual; es si la banda contiene el valor real y que tan amplia queda.

Capitulo VIII · Coverage y banda

La banda responde dos preguntas.

Coverage mide si el real cae dentro del intervalo. La banda mediana mide que tan ancho es ese intervalo.

Coverage = real entre p10 y p90
Banda % = (p90 - p10) / prediccion

Una banda puede tener mucho coverage porque es gigante. Eso no necesariamente es mejor para negocio.

Ejemplo verbal

Precio central: $50,000

Si p10=$45,000 y p90=$55,000, la banda mide 20%. Si el real fue $52,000, cuenta como cubierto.

Si hacemos p05/p95, probablemente cubre mas casos, pero puede decir "$40k a $60k". Es menos util para decidir precio.

mas cobertura no siempre es mejor

Capitulo X · Cierre

La conclusion para el profesor.

El modelo es bueno para prediccion central; la banda p10/p90 es util, pero se reporta honestamente con coverage observado.

Que intentamos

Baselines, modelos lineales, LightGBM, limpieza de outliers, validacion temporal, features geograficas y cuantiles.

Que decidimos

v5 con LightGBM, recencia, duracion de ruta y bandas p10/p90 para reportar incertidumbre.

Por que

Reduce error comercial, evita depender de R2 y comunica incertidumbre con una banda mas accionable.

Que falta

Recalibrar coverage por segmento, monitorear drift mensual y marcar baja confianza en segmentos con poca muestra.

Frase final

El resultado no se vende como perfecto: se vende como un modelo operativo, medible y honesto. Predice razonablemente bien y sabe decir cuando su intervalo no esta tan calibrado como quisieramos.
